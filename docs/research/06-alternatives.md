### ALT: ΔChunk — Stamped Delta-Pose Chunk Bridge with a Residual Cerebellum
ONE-LINE: Keep the two-model split and the pose interface, but make the pose a stamped 16-waypoint SE(3)-delta chunk (256 floats, 2–4 Hz) instead of one absolute waypoint, and demote Model B from "the command path" to a 3–18M clipped residual on top of analytic IK — Model A on the GPU, Model B on the CPU, a non-learned reflex layer underneath both.
MODEL A: CEREBRUM. Backbone: SmolVLA-450M (LeRobot/HF) — SmolVLM2-500M vision-language stack (SigLIP-base ViT + SmolLM2-360M), with SmolVLA's standard trick of keeping only the lower half of the LLM layers (16 of 32) and pixel-shuffling each camera to 64 visual tokens. Frozen backbone + LoRA r=32 on attention/MLP projections; only the LoRA (~8M) and the new heads (~12M) train. Total resident ≈450M params, ≈240M activated. Alternatives at the same slot: SmolVLM2-256M (2× faster, weaker grounding) or Florence-2-base 230M. NOT viable on this box: π0/PaliGemma-3B, OpenVLA-7B, Qwen2.5-VL-3B — measured 0.42 Hz for a 1.2B/256-token stack.

INPUTS: 2 RGB cameras (scene 224², wrist 224²) → 64 tokens each = 128 visual tokens; task text ≤20 tokens; 1 proprio token (EE pose 9 + joints n + gripper). Total sequence ≈150 tokens — the sequence length is as load-bearing as the parameter count (266M at 96 tokens = 4.3 Hz; the same 266M at 256 tokens = 1.4 Hz, measured).

OUTPUTS: one 256-float interface message (spec below) = a mixture of M=4 candidate 16-waypoint SE(3)-delta chunks, of which the argmax is emitted along with its mixture entropy. Plus two auxiliary heads used only in training: a next-subtask text head (the π0.5 "hierarchy-in-the-data" effect) and a per-waypoint reachability logit.

RATE: measured 234 ms p50 / 397 ms p99 for a 266M/96-token transformer stack on MPS fp16 on this exact M4 → budget Model A at 2–4 Hz, worst case 1.5 Hz when the machine is warm/loaded (I measured 1.5 s for an 805M/1024-token stack under load; that configuration is explicitly out of budget). A is NEVER on the critical path: it is event-triggered (chunk 60% consumed, gripper state flip, B's tracking error > τ, reachability reject, operator interrupt) rather than fixed-rate, because OpenHelix's sweep shows high-level frequency is nearly irrelevant (94/97/95/95/95/95/95 from every-step to once-per-episode) while RT-H shows the *moment* of replanning matters.
MODEL B: CEREBELLUM — and it is explicitly NOT the command path. Two pieces:

(B0) NON-LEARNED CORE, always on, zero training data: Pinocchio/TRAC-IK damped-least-squares inverse kinematics seeded with q_current (so branch selection is argmin‖q−q_prev‖ and joint-space continuity is a hard guarantee, not a learned hope), null-space gradient projection toward the swivel angle ψ that Model A ships in the interface, joint-limit and singularity avoidance. Runs at 200 Hz on CPU in microseconds-to-sub-millisecond. This alone is a complete, shippable v0 — it is the mandatory baseline.

(B1) LEARNED RESIDUAL, 3.2M (v0) → 18M (v1). Architecture: 4-layer pre-norm transformer, d=256 (v0) or d=384 with a 6-layer ViT-tiny patch encoder over ONE 128×128 wrist crop (v1). Inputs: decoded interface (256) + q, q̇ (2n) + measured EE pose in 6D-rot form (9) + wrench (6) + the IK core's proposed q_ik (n) + time-within-chunk and chunk-age (2) + previous residual (n) — a 32-dim state token in v0. Output: a residual joint chunk Δq over H=8 steps at 100 Hz (80 ms horizon), hard-clipped to ±2° per joint and ±5 cm/s EE-equivalent. Final command: q_cmd = IK(chunk_waypoint, seed=q_prev) + clip(f_θ(·)). Residual→0 recovers a fully working classical stack; a NaN or an out-of-distribution input produces dysmetria, not a full-speed slew — which is also the only version of the cerebellum analogy that survives contact with the anatomy (the real cerebellum has no motoneuron projection; its ablation is ataxia, not paralysis).

Optional but cheap and recommended: a forward-model head predicting q_{t+1} and next-step wrench from the efference copy of its own command. Free supervision from the same demos, it regularizes the representation, and its prediction error is the anomaly detector that triggers re-querying Model A.

RATE, measured on this M4 while a cerebrum-scale model saturated the GPU in a separate process, CPU-only with torch.set_num_threads(2), fp32:
  • 3.2M proprio-only: 1.17 ms p50 / 1.78 ms p99 → 858 Hz
  • 18M + 1×128px wrist crop: 6.29 ms p50 / 7.92 ms p99 → 159 Hz
  • 18M + 2×128px crops: 11.95 / 14.54 ms → 84 Hz
The same models on MPS: 23.6–43 ms p50 with 106–129 ms p99 tails (42 Hz / 23 Hz), i.e. 4× slower and 16× worse in the tail, AND they steal throughput from Model A. Model B goes on the CPU. This is the single change that makes genuine dual-rate execution real on Apple silicon without MLX's single-Metal-dispatch-queue problem, without CoreML/ANE conversion risk, and without two vision encoders on one GPU.

(B2) REFLEX LAYER, below everything, non-learned, in code not weights, running at 500–1000 Hz on the arm's own controller or a $60 Linux SBC over Ethernet (~0–4 ms, free): joint position/velocity/acceleration/jerk clamps, torque/current threshold with automatic retract, workspace AABB, self-collision check, finite-and-in-range assertion on every message, step-magnitude limiter (reject any command >N mrad from measured q), deadman watchdog that holds last-good then ramps commanded velocity to zero over 100 ms after 3 missed deadlines. Plus a reachability + collision filter applied to Model A's chunk BEFORE Model B sees it, which returns a typed rejection that re-triggers A rather than executing a hallucinated pose.
INTERFACE: A 256-float32 payload (1024 B) plus a 48-byte unlearned header. Emitted at 2–4 Hz event-triggered; consumed and re-interpolated by Model B at 100–160 Hz.

LEARNED PAYLOAD (256 floats, exact layout):
  [0:9]     anchor pose T_anchor in base_link — p(3) + 6D continuous rotation(6). The measured EE pose at image-capture time.
  [9:185]   16 waypoints × 11 floats:
              Δp(3)   translation delta from T_anchor, metres
              Δr6(6)  6D continuous rotation delta (Gram–Schmidt-decodable; never Euler, never raw quaternion)
              grip(1) continuous aperture 0..1
              dt(1)   seconds from anchor, monotone increasing
  [185:191] Cartesian stiffness scale (6-DoF, log-space, decoded to K_min..K_max)
  [191:192] force cap / damping ratio
  [192:194] redundancy: swivel (arm-angle) target ψ and its weight
  [194:195] mixture entropy of the M=4 chunk hypotheses (the "how sure am I" scalar; gate on it)
  [195:196] task-phase logit block index (approach / contact / transport / release)
  [196:256] 60-dim continuous latent side-channel from Model A's penultimate layer — the RoboDual pattern, carrying object identity, intent, and "be gentle" that six numbers cannot.

UNLEARNED HEADER (typed, versioned, asserted): capture_stamp (float64, monotonic clock), head/base joint state AT CAPTURE, frame_id (always "base_link" — see below), seq (uint32), validity_horizon (float32, default 500 ms), and a hash of (A-version, B-version, calibration-version) that B refuses to accept if it does not match its own.

FRAME CONTRACT: Model A predicts in camera frame (worth +8 to +14 points and roughly half the degradation under novel viewpoints, per OC-VLA), then A's own output stage immediately transforms to base_link using the head joint state timestamped at IMAGE CAPTURE, not at publish. Model B only ever sees base_link. This is the fix for the moving-head failure where a 300 ms inference delay and a 20°/s pan silently slide the target 6 cm.

WHY DELTAS: measured head-to-head on a real single arm, EE-absolute scores 69.0% vs EE-delta 89.6%, and chunk-wise delta beats step-wise by ~10 points (O(1) vs O(k) noise amplification). Deltas anchored on the measured EE pose also cancel the static component of the ~2.1 mm RMS / 3.2° hand-eye calibration bias, which an absolute target bakes in permanently and which Model B cannot see.

TRANSPORT: a lock-free shared-memory ring buffer (or ZeroMQ over loopback). 1 KB at 4 Hz is 4 KB/s — free. Images never cross the process boundary: Model A owns both cameras and writes the pre-decoded 128×128 wrist crop into a second shared buffer for B, so the expensive vision cost is paid once, not twice.

STALE POLICY, defined not implied: if (now − capture_stamp) > validity_horizon, Model B stops advancing the chunk, holds the last commanded pose, and decays commanded velocity to zero. It never extrapolates.
TRAINING: DATA
• Teleop: 200 episodes/task × 4–6 task families = 800–1200 episodes total, 30 fps, ~20 s each (≈130 k transitions). This is the standard 50–200 demos/task regime; below ~150/task the pose head over-fits object positions.
• Cheap non-teleop for Model A — this is where the split's actual leverage lives, and skipping it means paying every cost of the split for none of its benefit: 750–1500 single still frames of your scenes with the target gripper pose hand-annotated (RT-Affordance collected ~750 in 1 h and annotated them in 2 h; removing them dropped their predictor 77%→24%, and removing web co-training dropped it to 11%). Plus keep the VLM FROZEN so the internet prior survives — random-init vs pretrained is ~20 points on LIBERO, larger than any hierarchy premium in the literature.
• No extra data for Model B in v0 (it is analytic IK). v1's residual reuses the same teleop episodes.

STAGE 1 — Model A alone. LoRA on frozen SmolVLM. Chunk labels extracted by hindsight from teleop: anchor at t, waypoints at t+{1..16}·Δt with Δt≈100 ms; stiffness class auto-labelled from measured wrench magnitude; ψ read from the demo's actual elbow. Losses: winner-take-all L1 over the M=4 mixture heads on Δp and Δr6 (this is what prevents the frying-pan mode-averaging failure — an L2 head on a bimodal grasp lands in mid-air and looks fine in validation MSE), BCE on gripper, L1 on dt, CE on stiffness class and phase, Huber on ψ, BCE on the per-waypoint reachability logit, plus a next-subtask-text CE head that is trained but never run at inference. Co-train 50/50 teleop chunks and annotated stills.

STAGE 2 — Model B residual, separately, but NOT on ground truth. Train f_θ against the analytic IK core on the same demos with three mandatory augmentations: (a) target-pose noise sampled from Model A's MEASURED held-out error covariance, not from a guessed Gaussian; (b) artificial staleness sampled from the measured A-latency distribution (200–800 ms) so B learns to consume old targets the way HiRT trains its low level on cached latents; (c) posture perturbation on the seed configuration. Losses: L1 on the residual joint chunk, jerk penalty on the summed command, and a differentiable-forward-kinematics consistency term ‖FK(q_ik + Δq) ⊖ waypoint‖ — this is the kinematics-aware distillation that was the actual source of HDP's win, and it is what keeps the residual from drifting off the commanded Cartesian path.

STAGE 3 — MANDATORY DAgger round on the interface. Freeze A, roll it out on the training scenes, log real interface messages including its failures, relabel (hindsight or teleop correction), retrain B on that distribution. Add a GHIL-Glue-style progress filter that drops non-progressing chunks. Fixing only this handoff was worth +25% on CALVIN and 54%→70% on a real robot; GHOST's oracle swap was 36.7%→90%. Skipping Stage 3 is the single most likely reason a first build underperforms the monolith.

STAGE 4 — OPTIONAL, cheap, high-value: partial joint finetune. The 60-dim latent and the Δpose floats are continuous, so you can backprop B's loss into A's HEAD ONLY (VLM stays frozen) through those channels while the human-readable pose semantics are preserved by keeping Stage 1's supervised losses active. This is OpenHelix's "pre-align the projector" in its cheapest form — without it, they measured 0/0/0/0/0 across every configuration. Trainable on this Mac mini in hours; Stages 1–2 are a single-GPU job (rent an A100 for ~8–20 h, ~$20–60, or run SmolVLA-scale LoRA overnight on the M4 itself).

GATES BEFORE ANY OF THIS. Two one-week controls that can kill the whole architecture cheaply: (1) monolithic SmolVLA-450M + action chunking + real-time chunking / async execution — same measured 2–4 Hz backbone, smooth 30–50 Hz commands, ~30% faster completion and 2× throughput for ~50 lines of code; (2) one model with an auxiliary target-pose prediction head and NO runtime hierarchy — π0.5's own "implicit HL" ablation was second-best and their conclusion was that most of the benefit comes from having the decomposition in the training mixture. If either matches ΔChunk on a properly powered eval, build that instead.

EVALUATION. ≥50 rollouts per task per condition (TRI needed 1800 trials with Bonferroni correction to separate policies; HiRT's split-vs-monolith gap on static tasks was 1.3 points, in the monolith's favour). Test on DYNAMIC scenes with moving targets and external disturbances and on LONG-HORIZON multi-stage tasks — those are the only regimes where any published hierarchy advantage reliably appears (+27 and +30 to +42 points respectively; on short-horizon pick-and-place it is a measured tie, 69.57% vs 69.63%). Ship two attribution harnesses on day one: Oracle-A (replay ground-truth chunks into B) and Oracle-B (swap B for pure IK + impedance, feed A's live chunks). Without them, every failure has four indistinguishable causes.
BETTER: The rate decoupling is REAL on this hardware and I measured it, rather than assuming it. Model A on the GPU (234 ms p50 / 397 p99 for a 266M/96-token stack) and Model B on the CPU (6.29 ms p50 / 7.92 p99 for the 18M+wrist-crop config, taken WHILE the GPU was saturated by a cerebrum-scale model) run genuinely in parallel on different compute units. The original design's two-Metal-models arrangement measured 23.6–43 ms p50 with 106–129 ms p99 tails and total latency = A + B, strictly worse than one monolith. Moving B to the CPU is a one-line change (device='cpu', set_num_threads(2)) that converts the split from a fiction into a 25–140× rate ratio. | Model B can no longer produce a class of failure that the original could. Seeding analytic IK with q_current and taking argmin‖q−q_prev‖ makes branch selection a hard continuity guarantee, killing the mode-averaging failure (mean of elbow-up and elbow-down is a configuration whose FK is nowhere near the target) and the branch-flip failure (180° wrist slew in one control step) that a learned pose→joint regressor cannot structurally avoid and that gets WORSE with more data. The residual is clipped to ±2°/joint, so the worst learned-component fault is dysmetria, not a full-authority slew. | The interface carries the things that decide task success and that a bare 7-vector silently drops: gripper aperture per waypoint (removing the approach-vs-close ambiguity at an identical pose that would otherwise make Model B's learning problem formally ill-posed), dt (a waypoint with no time is not a trajectory; approach speed is what sets impact force), Cartesian stiffness (worth +23.2 to +38.0 points in the force-aware VLA literature), and the swivel angle ψ (the ER/ERJ measurement is 8% → 94% on confined-space tasks for ONE extra scalar). | Chunk-wise SE(3) deltas anchored on the measured EE pose recover ~20 points over absolute waypoints on the only clean head-to-head available (89.6% vs 69.0%), and cancel the static component of the ~2.1 mm / 3.2° hand-eye calibration bias that an absolute target bakes in as a systematic, unobservable, uncorrectable offset. 6D continuous rotation removes the quaternion/Euler wrap-around discontinuity as a free source of regression error. | Chunking makes the cerebrum's slowness irrelevant instead of fatal. A 16-waypoint chunk covering ~1.6 s at 2–4 Hz means A can be 250–700 ms late and the arm still moves smoothly; chunk length is nearly free in latency (5→250 actions costs ~11% end-to-end) while denoising steps are expensive (10→50 costs 5×), so this design uses long chunks, a regression head, and no autoregressive action tokens (which carry a ~102× penalty). | The interface stays inspectable, which is the one advantage a pose has over a latent and the one that historically paid off most: RT-H's biggest single number was not the hierarchy (+15%) but human motion-level correction (40% → 63%, beating IWR by 50%). Every ΔChunk message renders in RViz as a 16-waypoint ribbon with gripper state and stiffness colour-coded, is draggable with a 6-DoF mouse, is replayable offline through Model B without the robot, and is unit-testable. The 60-dim latent side-channel restores the bandwidth a pose lacks without giving up any of that. | Failure is contained and typed rather than executed. The reachability/collision filter rejects a hallucinated chunk before Model B ever sees it (Model A's operating regime is 24–37% wrong in the published oracle ablations — that is normal, not the tail); the analytic IK core returns 'no solution / at joint limit / near singularity' as a branchable event; the deadman watchdog and stale policy define what happens on the missed deadlines that my own p99 measurements show are routine. The original design had no layer capable of detecting any of this because Model B was the bottom layer. | It buys the split's actual, evidenced benefit — data access at the high level. Model A consumes 750–1500 hand-annotated stills and a frozen internet-pretrained VLM, neither of which a joint-space low level can use. That is the mechanism behind RT-Affordance (77% → 24% without the stills, → 11% without web co-training) and HAMSTER (1.2M off-domain samples up top, 320 in-domain episodes below), and it is the only performance argument for the split that survives scrutiny. | The capacity split is now lopsided in the direction every working system uses — 450M : 3–18M, a 25–140:1 ratio, matching Helix (87:1), RoboDual (350:1) and π0 (10:1) — instead of the evenly-split, both-trained-from-scratch arrangement that has zero supporting evidence and forfeits the ~20-point pretraining effect. | Every piece degrades to something that works. Delete the residual → analytic IK + impedance, a complete system. Delete Model B entirely → the reflex layer still holds the arm safe. Delete the latent channel → a plain pose interface. Delete the stills → a weaker but functioning Model A. There is no configuration of this design that is inert, which was not true of the original.
WORSE: It still cannot claim the thing the original set out to prove. Splitting a fixed parameter budget across two models to improve task success is not supported by anything in the literature — HiRT's monolith beat its hierarchy 71.3 vs 70.0 on real quasi-static tasks, naive hierarchy tied a flat VLA 69.57 vs 69.63 on short-horizon, and π0.5's own ablation found the runtime split mostly redundant with having the decomposition in the training data. ΔChunk is justified by latency, data access, safety and debuggability. If the goal is genuinely 'higher success rate on tabletop pick-and-place', the honest answer is still a monolithic SmolVLA with action chunking, and this design will at best tie it. | It is materially more engineering than a monolith: two processes, a versioned interface schema, a shared-memory transport, a frame/timestamp contract, a reflex layer, a DAgger relabeling round, and two attribution harnesses. Call it 4–6 weeks of systems work before the first honest number, against roughly one week for monolith + real-time chunking. Much of that work is unavoidable safety plumbing, but it is not free and it is not modelling. | The 60-dim latent side-channel is a hedge that partially undercuts the interface's clean semantics. It is only supervised by Stage 4's partial joint finetune; if you skip Stage 4, the latent is untrained noise that Model B will learn to ignore, and you are back to a pose-only bottleneck. If you run Stage 4, the interface is no longer purely human-specified and a bad gradient can quietly corrupt the pose head. | Model B remains near-saturated, so its capacity is close to wasted. GHOST's oracle swap (36.7% → 90% by changing only the high level) and RT-Affordance's predicted-vs-oracle gap (68% vs 76%) both say the residual error lives in Model A. The 3–18M residual will most likely show a 1–3 point effect that a 50-rollout evaluation cannot separate from noise. Expect the honest v1 result to be 'the residual did nothing measurable; the classical core did the work', and be prepared to ship B0 and delete B1. | A camera-fed Model B is hard-capped at camera frame rate. The measured 159 Hz for the 18M+crop config is meaningless above 30–60 fps of actual visual novelty, so the reflex-layer story is really 'proprioception at 858 Hz, vision at 30 Hz'. Anyone reading '159 Hz cerebellum' will over-estimate its reactivity. | The compliance channel is void on the wrong hardware. If the arm exposes only joint position commands, the 6-DoF stiffness field and the whole contact-adaptation rationale for a learned residual evaporate, and ΔChunk collapses to a well-plumbed version of keypose + IK. Verify the arm has torque, admittance or variable-stiffness control BEFORE building this; if it does not, scope the tasks to free-space pick-and-place in writing. | Model A at 2–4 Hz remains the reactivity ceiling for anything semantic. If an object slips or a human moves the target, the system cannot re-plan WHERE faster than ~300–700 ms no matter how fast B runs. The residual can track a moving chunk but cannot invent a new grasp. Genuinely dynamic manipulation needs a bigger box, not a better interface. | Cross-process co-residency is not free: when I ran the CPU-side Model B at 2–4 threads alongside the GPU model, the cerebrum degraded to ~1.5–1.8 s per forward pass on a loaded machine. Model B must be capped at 2 threads and Model A must be treated as a 1.5–4 Hz service with high variance, not a 4 Hz clock. On a thermally-loaded Mac mini this is the design's weakest joint. | The DAgger round in Stage 3 is re-entrant: every retrain of Model A, every frame-convention change, and every hand-eye recalibration invalidates Model B's training distribution. The (A-version, B-version, calibration-version) hash in the header catches the mismatch at runtime, but the maintenance cost is real and recurring, and it does not exist for a monolith. | Nothing here is novel. Stripped of the naming, ΔChunk is the PerAct/RVT keypose-plus-planner family with a chunked delta interface, a RoboDual-style latent side-channel, and a residual-RL low level. That is a feature for shipping and a liability if the goal was a research contribution — the one genuinely untested configuration in this space was the original proposal's learned pose→joint low level, and it is untested because it does not work.
COST: RUNS ON THE MAC MINI — yes, and I measured it on this exact box (Apple M4 base, 10 CPU cores 4P/6E, 10-core GPU, 32 GB unified, kern.sched=edge, PyTorch 2.11, batch 1, machine under ~2–8 load average, so these are conservative).

PLACEMENT AND MEASURED RATES
• Model A — GPU (MPS fp16, or MLX int8 for ~1.5–2× more headroom and half the footprint). 266M params over 96 tokens: 234 ms p50 / 397 ms p99 → 4.3 Hz. Same params at 256 tokens: 729 ms → 1.4 Hz. A 1.2B/256-token stack: 2357 ms → 0.42 Hz. Design budget: SmolVLA-450M with ≤150 tokens, 2–4 Hz nominal, 1.5 Hz worst case under thermal/CPU load. Token count is as expensive as parameters — keep both cameras at 64 pixel-shuffled tokens.
• Model B — CPU ONLY, torch.set_num_threads(2), fp32, measured concurrently with a saturated GPU: 3.2M proprio-only 1.17 ms p50 / 1.78 ms p99 (858 Hz); 18M + one 128² wrist crop 6.29 / 7.92 ms (159 Hz); 18M + two crops 11.95 / 14.54 ms (84 Hz). Do NOT put Model B on MPS: the identical models measured 23.6–43 ms p50 with 106–129 ms p99 (42 / 23 Hz) — 4× slower, 16× worse tail, and it steals GPU throughput from Model A. This CPU/GPU partition is why no MLX single-dispatch-queue workaround and no CoreML/ANE conversion gamble is needed; ANE remains available as a later optimisation, not a dependency.
• Servo — NOT on the Mac. macOS has no RT class, no PREEMPT_RT, no isolcpus, no SocketCAN, no EtherCAT, and ROS 2 is REP-2000 Tier 3 (source build only, no CI). Run the 500–1000 Hz joint/impedance loop on the arm's own controller, or on a $60–150 Raspberry Pi 5 / Intel N100 over wired Ethernet (measured cost of that hop in the literature: 0–4 ms, i.e. free). The Mac emits 100–160 Hz setpoints and is an inference server only — a role it is genuinely good at.

MEMORY
Model A: 450M at int8 ≈ 0.5 GB, at fp16 ≈ 0.9 GB. Model B: 18M fp32 ≈ 0.07 GB. Activations + KV ≈ 0.5 GB. Two camera ring buffers ≈ 0.5 GB. macOS + WindowServer ≈ 4–5 GB. Total ≈ 6.5–7 GB against 32 GB available — this design fits comfortably on a 16 GB Mac mini, which the original (two vision encoders, both on the GPU) does not. Unified-memory BANDWIDTH is not the binding constraint (~45–70 GB/s demand against 120 GB/s on M4 base); GPU compute and Metal dispatch are.

CONTENTION CAVEAT, measured: with Model B running 2–4 CPU threads alongside, the GPU cerebrum degraded to ~1.5–1.8 s per pass on a loaded machine. Cap Model B at 2 threads, treat Model A as a 1.5–4 Hz service with high variance, and let action chunking absorb it. The alternative is not a better Mac — it is a different box.

COST
$0 additional if the arm has its own real-time controller; $60–150 for an SBC if not. Training Stages 1–2 are a single-GPU job: ~8–20 h on a rented A100 (~$20–60), or overnight LoRA on the M4 itself for the 450M configuration. Annotation: ~3 h of human time for the 750–1500 stills. Teleop: 800–1200 episodes ≈ 8–15 h of operator time.

FOR COMPARISON, so the trade is explicit: the same architecture on a used RTX 3090/4090 desktop on the same wired switch would run Model A at roughly 25–30 Hz (~8–10× this box) with genuine CUDA priority streams, TensorRT int8 that actually accelerates compute rather than just shrinking footprint, and no macOS real-time objections at all — for roughly the price of the Mac mini. If the Mac is a constraint, ΔChunk is the right shape for it. If the Mac is a preference, buy the GPU box and run a monolith.

### ALT: TRISYS-500 — frozen-VLM System-2 + flow-matching action expert + analytic spinal layer (one model, two weight sets, three clock domains)
ONE-LINE: A π0.5/GR00T-shaped dual-system VLA where System-2 is a frozen pretrained SmolVLM2-500M whose mid-layer hidden states (not a pose) are the interface, System-1 is a ~100M flow-matching action expert living in the SAME forward graph that emits 50-step chunk-wise SE(3)-delta action chunks, and a non-learned analytic spinal layer (TRAC-IK + impedance + hard clamps) runs off-Mac at 500–1000 Hz — with target-pose and language-subtask prediction kept as auxiliary training losses rather than as the runtime interface.
MODEL A: SYSTEM 2 ("대뇌"). Backbone: SmolVLM2-500M-Video-Instruct — SigLIP-base vision tower (~93M) at 256–512 px with pixel-shuffle to 64 tokens/frame, plus SmolLM2-360M decoder (32 layers, d=960, mlp 2560). Following SmolVLA, only the FIRST 16 of 32 decoder layers are executed (layer skipping); the upper 16 are deleted at export. Executed params ≈ 93M vision + ~177M LM = 270M; checkpoint 500M. The VLM is FULLY FROZEN in both stages (GR00T N1.5 recipe — freezing plus an adapter/LayerNorm fix is what took real GR-1 success 43.3% → 83.0%; it is also the only tractable option locally). Inputs: 2 RGB cameras (base/overhead + wrist) at 256×256, natural-language task string (≤48 tokens), and the current EE pose + joint vector discretized to text tokens (π0.5's trick — keeps the frozen VLM's tokenizer path intact). Outputs at runtime: NOTHING human-readable in the control path — it emits hidden states, see `interface`. Two AUXILIARY heads hang off the pooled prefix and are used at TRAINING time only (and optionally decoded at 1 Hz for logging/RViz): (a) a 3-keyframe SE(3) target-pose head, 3×(3 translation + 6D rotation + 1 gripper) = 30-d, which is the user's original Model A output demoted to a supervision signal; (b) a language subtask head (π0.5's "explicit HL"). Rough FLOPs: 2 cams × 2·93M·256 ≈ 95 GFLOP vision + 2·177M·176 ≈ 62 GFLOP prefill = ~157 GFLOP. On the measured 3.80 TFLOPS roofline at ~50% achieved utilization → ~83 ms compute-bound, ~5–8 Hz measured-realistic with framework overhead. Runs event-triggered, NOT at a fixed high rate.
MODEL B: SYSTEM 1 ("소뇌" — but explicitly NOT an IK box). A flow-matching action expert: DiT-style, 16 layers, width 720 (= 0.75 × VLM width, SmolVLA's ratio), MLP 1920, 8 heads, ~100M params, ALL TRAINABLE. Each block interleaves (i) self-attention over [1 state token ⊕ 50 noised action tokens ⊕ 16 wrist-crop tokens] with (ii) cross-attention into the cached System-2 prefix. Its own fresh perception — required, this is what makes it a genuine dual system rather than π0/GR00T (OpenHelix excludes those on exactly this criterion) — is a 128×128 wrist crop through a 4-layer conv stem (~3M params, ~1–2 ms), NOT a second ViT. That single choice is the difference between viable and dead: a full ViT-B/16 encoder measures 62.75 ms p50 solo and 214 ms p50 / 289 ms p99 under GPU contention on this box, which would cap System-1 at 4.7 Hz — slower than System-2 was supposed to be. Other inputs: joint positions + velocities (14-d bimanual or 7-d single), 6-d wrench if the arm has an F/T sensor, and the age-of-Φ scalar (so it knows how stale its conditioning is). Inference: K=4 Euler flow steps (VLA-Perf: 10→50 steps costs 5×; chunk length is nearly free at +11% for 5→250). Per step ≈ 2·100M·67 ≈ 13.4 GFLOP → ~7 ms compute-bound, ~15–18 ms realistic; K=4 → 60–72 ms per chunk → 14–17 Hz chunk generation. Optional 5th head: a forward model predicting next joint state + next wrist-crop embedding from its own efference copy (auxiliary loss, weight 0.05) — this is the one function that actually defines a cerebellum, it costs nothing, and its prediction error becomes the runtime anomaly trigger that re-queries System-2.
INTERFACE: TWO tensors, both learned, both differentiable, neither a pose.

DOWNWARD (S2 → S1), the "latent": Φ = Adapter(h^(16)) where h^(16) ∈ R^[176 × 960] is the hidden state at decoder layer 16 (mid-layer, GR00T N1's layer-12-of-N choice; also the last layer of the truncated stack), 176 tokens = 2×64 visual + 48 language/state. Adapter = LayerNorm → Linear(960→720) → GELU → Linear(720→720) → LayerNorm (the LayerNorm-on-both-sides fix is specifically what GR00T N1.5 credits for its jump). Φ ∈ R^[176 × 720] fp16 = 253 KB. It is then pre-projected once into per-layer cross-attention K/V: 16 layers × 2 × [176 × 720] ≈ 8.1 MB, cached. UPDATE RATE: 5–8 Hz nominal, plus EVENT-TRIGGERED re-query on (a) gripper state transition, (b) System-1 forward-model error > τ, (c) typed IK-infeasible from the spinal layer, (d) chunk-progress stall, (e) operator interrupt. Fixed-rate high-frequency updates are explicitly rejected — RT-H found one-step-ahead async beats fixed-frequency because skills change at precise moments, and OpenHelix's sweep found every-step vs once-per-60-step-episode is a wash (94/97/95/95/95/95/95). Critically: gradients FLOW BACKWARD through Φ into the adapter (and would flow into the VLM if it were unfrozen — Helix backprops S1→S2 through exactly this vector). There is no serialized IPC hop: S2 and S1 are one PyTorch/MLX graph in one process, S1 just re-runs many times against the cached prefix. This kills the MLX single-Metal-dispatch-queue problem (issue #3078) outright, because there is never a second process contending.

UPWARD (S1 → S2): a 4-scalar status vector [forward-model error, chunk-progress fraction, min IK manipulability over the chunk, gripper-contact flag] — the closed-loop return path the original one-directional design lacks (Kelly & Strick: cerebro-cerebellar circuits are closed loops).

DOWNWARD (S1 → spinal layer), the action chunk: A ∈ R^[50 × 12] fp32 = 2.4 KB, at 14–17 Hz. Per-step channels: Δposition (3), 6D continuous rotation (6, never Euler, never raw quaternion), gripper aperture (1, continuous), stiffness level (1, or a 3-level discrete flag), swivel/arm angle (1, the ERJ redundancy scalar). ALL DELTAS ARE CHUNK-WISE — relative to the measured EE pose at chunk start, not absolute and not step-wise. This is the single highest-value correction available: measured EE-absolute 69.0% vs EE-delta 89.6% on a real single-arm platform, and chunk-wise beats step-wise by ~10 points with an O(1)-vs-O(k) noise-amplification argument. Chunk-wise delta also cancels most of the ~2.1 mm RMS / 3.2° hand-eye calibration bias, because both endpoints carry the same bias. H=50 at 30 Hz execution = 1.67 s horizon; re-plan fires when the queue drains to 70% (SmolVLA's g=0.7), i.e. every ~500 ms, with 3× headroom over S1's 60–72 ms. Real-Time Chunking inpainting freezes the already-committed prefix so consecutive chunks join without boundary jerk.

LAYER 0 (non-learned, NOT a model, NOT on the Mac): chunk → compose deltas onto pose-at-chunk-start → Ruckig jerk-limited interpolation to 500–1000 Hz → TRAC-IK (>99.8% success, sub-ms) with null-space posture bias, or Cartesian impedance τ = Jᵀ(K(x_d−x) + D(ẋ_d−ẋ)) + g(q) if torque-capable. Hard gates: joint pos/vel/acc/jerk clamps, workspace AABB, self-collision, reachability rejection, torque-threshold retract, finite/NaN assert, step-magnitude limiter, deadman watchdog that ramps velocity to zero after 2 missed deadlines. IK infeasibility returns a TYPED error — the thing a regression network structurally cannot produce — which propagates up as an S2 re-query trigger.
TRAINING: STAGE 0 — do not train from scratch. Initialize from the public SmolVLA-450M checkpoint (pretrained on ~23k LeRobot community episodes across 481 datasets). Random-init vs pretrained VLM is 77.5% → 97.8% on LIBERO, ~20 points, which is larger than any short-horizon hierarchy premium in the entire literature. Forfeiting this is the single biggest cost of "two locally-trained-from-scratch models."

STAGE 1 — adapter pre-alignment (2–4 h on a rented GPU). Freeze the VLM. Train ONLY the adapter with the two auxiliary heads (keyframe-pose + subtask-language) and a CLIP-style alignment loss, no action head. This is non-optional: OpenHelix Table 6 shows that WITHOUT projector pre-alignment, every dual-system configuration scored 0/0/0/0/0. With it, 94–96% first-task success.

STAGE 2 — joint co-training (24–48 h on one A100 / RTX 4090; NOT on the Mac — 3.8 TFLOPS makes local training a non-starter). VLM stays frozen; adapter + action expert + wrist stem + all heads train together with gradients crossing Φ. Data mixture per batch:
  • 60% — YOUR teleop: 250–400 episodes over 8–12 tasks (~30/task, 5–7 h of teleop). Justification for that number: π0 uses 50–200 bimanual demos/task from scratch; TRI measured that finetuning a pretrained LBM needs <30% of from-scratch data; SmolVLA reports 60% average at 200/task. 300 episodes on top of a pretrained checkpoint is the right budget, and it is ~1/2 of what the original two-model plan needs (which requires a second, sequentially-collected dataset for Model B).
  • 15% — ~750 hand-annotated still images with the gripper outline drawn at key stages, ~1 h to collect, ~2 h to label. This is the actual source of leverage in every hierarchy that works: RT-Affordance's predictor drops 77% → 24% without exactly these images, and → 11% without web co-training. If both halves only ever see your teleop, you pay all the split's costs for none of its benefit.
  • 15% — web VQA / grounding batches, to prevent catastrophic forgetting (π0.5: removing web data degrades significantly).
  • 10% — subtask-language labels, ~2500 phrases auto-extracted at gripper open/close transitions with zero human labeling (RT-H's method).
Losses: L_flow (conditional flow matching, π0's objective, beta-sampled τ) weight 1.0; L_pose (smooth-L1 on the 30-d keyframe SE(3) head off Φ) weight 0.1 — this is where the user's original Model A output lives, and OpenHelix's Table 7 shows forcing the latent to predict position/rotation was their single largest gain, avg length 3.45 → 4.01; L_lang (CE on subtask tokens) weight 0.1 — π0.5's own ablation found "implicit HL" (subtask data in the mixture, NO high-level inference at runtime) was second-best overall, i.e. most of the hierarchy benefit is a DATA effect and this loss captures it; L_fwd (forward model off S1's efference copy) weight 0.05.

STAGE 3 — staleness conditioning. Re-run the last 20% of training with Φ artificially delayed by latencies sampled from the MEASURED on-robot distribution (on this M4: S2 p50 ~130 ms, p99 ~500 ms). HiRT explicitly caches the latest latent and trains the low level against stale conditioning; skipping this is a covariate shift you will misdiagnose as a modelling problem for weeks. This also structurally removes the two-separately-trained-models failure that GHIL-Glue measured at +25% CALVIN / 54%→70% real-robot and GHOST measured at 36.7% vs 90% oracle.

STAGE 4 — optional, 50–100 additional on-robot intervention episodes. Operator corrects via 6-DoF mouse during autonomous rollout; corrections are logged and folded back in. RT-H's biggest single number was not the hierarchy (+15%) but intervention learning: 40% → 63%, beating IWR by 50%.

### ALT: CIR-1 "Cortex–Impedance–Residual" (대뇌 하나 + 척수)
ONE-LINE: Delete Model B. Put 450M parameters in one pretrained VLA that emits chunk-wise Cartesian *delta* waypoints with stiffness and gripper, hand them to TRAC-IK + Cartesian impedance running on the robot's own controller at 1 kHz, and add exactly one learned thing at the bottom: a 0.18M-parameter, camera-free, hard-clipped force residual that is *summed onto* the classical controller so residual→0 recovers a fully working robot.
MODEL A: WHAT IT IS. `lerobot/smolvla_base` (SmolVLA-450M) fine-tuned: SigLIP-B/16 vision tower ~93M + SmolVLM2-500M-Video LM trimmed to its first 16 layers ~190M + 100M flow-matching action expert. Chosen because it (a) already runs on MPS today via LeRobot's `--policy_device=mps`, (b) already ships the async PolicyServer/RobotClient with chunk queues and weighted-average temporal ensembling, (c) already beats OpenVLA-7B on LIBERO (87.3 vs 76.5) at 1/15th the size, and (d) is internet-pretrained, which is the ~20-point lever (LIBERO random-init 77.5% vs pretrained 97.8%) that a from-scratch local split throws away.

INPUTS. 2× RGB 224×224 (scene + wrist) → 64 tokens/frame after pixel-shuffle; language instruction ≤32 tokens, with an explicit `attempt=k` field appended so a retry is not a bitwise-identical query (this is the anti-livelock fix); proprio state 23 floats (joint pos 7, gripper 1, EE pose as translation+6D-rotation 9, measured wrench 6) discretized into state tokens. ~256 tokens total context.

OUTPUTS. Not a single absolute SE(3) waypoint — that is the worst-measured abstraction (EE-absolute 69.0% vs EE-delta 89.6% on the one clean head-to-head) and it permanently bakes in the ~2.1 mm RMS / 3.2° hand-eye calibration bias. Instead: a chunk of 16 Cartesian **delta** waypoints referenced to the *measured* EE pose at chunk start, each carrying [Δp(3), 6D-rotation(6), gripper aperture(1), dt(1)], plus a per-chunk header of [log-stiffness(6), swivel/arm-angle(1), confidence(1), phase(1)]. Auxiliary heads (train-time, cheap, and load-bearing): subtask-string prediction (π0.5's own ablation says most of the hierarchy benefit lives in this training signal, not in a runtime split) and explicit position/rotation prediction (OpenHelix's single largest gain, avg length 3.45 → 4.01).

PARAMS. ~450M total, ~99.96% of all learned parameters in the system. The split is 2,500:1 in favor of the high level — more lopsided than Helix (87:1) or RoboDual (350:1), and deliberately so: every oracle ablation says the residual error lives here (GHOST froze the low level, swapped the high level, and went 36.7% → 90%).

RATE. Measured end-to-end on this M4: vision 60.6 ms/cam + LM prefill 150.0 ms + action expert (4 flow steps) 17.8 ms ≈ 230 ms single-cam / ~290 ms dual-cam → **3.4–4.3 Hz** in eager PyTorch/MPS. With MLX int8 and vision-feature caching across a chunk, budget 6–10 Hz but do not plan on it. Run it **asynchronously and event-triggered**, never on a fixed clock: OpenHelix's sweep found running the high level every step vs once per 60-step episode is a wash (94/97/95/95/95/95/95), so frequency is not where the engineering should go — triggers are.

HARD CEILING, MEASURED: a 3B trunk prefill takes 3.74 s on this box (0.27 Hz). "Spend all the capacity on the high level" tops out at ~0.5–1B on an M4 base. A π0.5-class cerebrum must move to a Linux+RTX host; wired-GbE round trip costs ~0–4 ms, i.e. free.
MODEL B: Three stacked layers replace the proposed "cerebellum". Only the third has weights, and it has 0.18M of them.

(1) RETIMER — 0 params, ~0 compute, robot host. Ruckig jerk-limited online trajectory generation over the 16-waypoint chunk → 200 Hz Cartesian setpoint stream (pose, twist, stiffness). Real-Time-Chunking prefix freezing + weighted-average ensembling over the chunk overlap, so consecutive chunks join without the boundary jerk that plain chunking produces. This layer alone is what buys the control rate — SmolVLA measured equal success, ~30% faster completion (9.7 s vs 13.75 s) and 2× throughput from async chunked execution on ONE model. It is ~50 lines, not a neural network.

(2) CLASSICAL LOW LEVEL — 0 params, on the arm's own controller. TRAC-IK (>99.8% solve rate sub-millisecond vs ~96% for stock KDL) or IKFast if the arm has a closed form (5–50 µs); measured here, a raw damped-least-squares 6×7 solve is **5.31 µs → 188 kHz**. Seeded with q_current and selecting argmin‖q − q_prev‖, which gives a *hard branch-continuity guarantee* no regressor can provide — this is the direct fix for the elbow-up/elbow-down mode-averaging failure, where an L2-trained network emits the arithmetic mean of two valid branches and the resulting FK is nowhere near the commanded pose. Nullspace posture bias driven by the swivel angle in A's header (the ERJ scalar that takes confined-space success from 8% → 94%). Then Cartesian impedance τ = Jᵀ[K(x_d−x) + D(ẋ_d−ẋ)] + nullspace + gravity/Coriolis compensation, K from A's log-stiffness channel, at 500–1000 Hz.

(3) RESIDUAL REFLEX — 0.183M params, the ONLY learned thing below the interface. Two-layer GRU (h=128) + 2-layer MLP head. Inputs, 44 dims: joint pos 7, joint vel 7, measured wrench 6, Cartesian pose error 6, twist error 6, commanded log-stiffness 6, phase one-hot 4, time-in-chunk 1, plus its own recurrent state. **No RGB, no camera, ever.** Output: 6-dim Cartesian wrench correction ΔF, hard-clipped to ±8 N / ±0.8 Nm, **added to** the impedance controller's output (Kawato feedback-error-learning structure). Plus a forward-model auxiliary head that predicts, from its own emitted correction (efference copy) plus current state, the next 5 ms of wrench and joint state — free supervision, a latency compensator, and the runtime anomaly signal that triggers re-querying A.

MEASURED: **0.05 ms p50 / 0.06 ms p99 on one CPU thread** — 1 kHz with 20× headroom, no GPU, no ANE conversion risk, no MLX dispatch-queue contention. Compare: a ViT-B/16 encoder, the minimum a camera-fed Model B would need, costs 60.6 ms p50 idle and was measured at 214 ms p50 / 289 ms p99 under GPU contention from a concurrent cerebrum — i.e. a camera-fed low level is *slower than the high level was supposed to be*, and is capped at camera frame rate (30 fps) regardless of accelerator speed.

WHY THIS ISN'T "MODEL B WITH EXTRA STEPS": it does exactly one thing that IK cannot — cancel the tracking error the impedance controller fails to close, using force and proprioception. That job fits in one sentence, has a matching classical baseline (fixed-gain impedance), and is measurable in newtons. It is not doing IK, not doing motion planning, and not doing visual servoing. If you later want visual servoing to cancel A's calibration bias, that is a *different* module with an image-space goal running at camera rate, benchmarked against classical uncalibrated IBVS with online Jacobian estimation — build it separately or not at all.

SAFETY LAYER, below everything, in code not weights, built first: joint position/velocity/acceleration/jerk clamps; workspace bounding box + reachability + self-collision filter applied to A's target *before* the retimer sees it; motor-current/wrench threshold with automatic retract; finite-and-in-range assertions at three points (A's output, residual output, servo input) with reject-and-hold rather than pass-through; step-magnitude limiter rejecting any joint command >N mrad from measured configuration; deadman watchdog that holds last-good then ramps velocity to zero after K missed deadlines. Ablate the residual and you get dysmetria (sloppy tracking), not paralysis — which is the actual cerebellar phenotype, and the reason this variant is safe to run unattended while the proposed design is not.
INTERFACE: A typed, timestamped, versioned, schema-pinned message — not a bare 7-vector on a topic.

```c
struct ChunkMsg {                 // 189 float32 (756 B) + 16 B ints ≈ 772 B on the wire
  uint64  t_capture_ns;           // CAMERA SHUTTER time, not publish time
  uint32  seq;
  uint16  schema_ver;             // pinned; (A_ver, residual_ver, calib_ver) is ONE artifact
  uint8   frame_id;               // == base_link, ALWAYS
  uint8   attempt;                // retry index; also fed back into A's prompt
  float32 head_q[3];              // head/base joint state AT CAPTURE (audit + assert)
  float32 valid_horizon_s;        // default 0.75

  // --- per-chunk header: 9 floats
  float32 log_stiffness[6];       // EE-frame trans+rot, log10 N/m and Nm/rad
  float32 swivel_angle;           // 7-DoF null-space arm angle; ignored on 6-DoF
  float32 confidence;             // 1 - normalized entropy over 8 flow-expert samples
  float32 phase;                  // 0 free / 1 approach / 2 contact / 3 retract

  // --- 16 waypoints x 11 floats = 176
  float32 wp[16][11];             // [dp(3), rot6d(6), gripper_aperture(1), dt(1)]
                                  // DELTAS w.r.t. MEASURED EE pose at chunk start
};
```

DIMENSIONALITY: 189 float32 payload = 756 B. Every field is there for a measured reason. Deltas not absolutes: EE-delta 89.6% vs EE-absolute 69.0%, and deltas cancel the static hand-eye calibration bias because both endpoints share it. Chunk-wise not step-wise: ~10 points better, O(1) vs O(k) noise amplification. 6D continuous rotation, never Euler or raw quaternion — the wrap-around discontinuity is a free source of regression error. Gripper aperture is non-optional (HDP's published interface is literally (a_trans, a_rot, a_grip)) — without it, approach-open and close-at-the-same-pose are the same conditioning with different labels, and the policy emits a half-closed gripper. `dt` is non-optional: a waypoint with no duration is not a trajectory, and approach speed is what determines impact force. Stiffness is non-optional for contact (ForceVLA +23.2% over π0; FAVLA +38.0 points over vision-only π0). Swivel is non-optional on 7-DoF (8% → 94%).

FRAME CONTRACT, enforced in code: A predicts in camera frame (worth +8 to +14 points, and roughly half the degradation under novel viewpoints), then **converts to base_link immediately at A's own output** using the head joint state timestamped at image capture. A camera-frame target never survives an inference delay. At 4 Hz with a head panning 20°/s, 250 ms of unstamped delay is ~6° ≈ 63 mm of lateral error at 0.6 m — an intermittent, undebuggable failure that presents as a perception bug.

STALENESS POLICY, defined not emergent: if `now - t_capture > valid_horizon_s`, the retimer holds the last valid setpoint and ramps commanded velocity to zero. It never extrapolates. Measured p50→p99 spread on A is ~128 ms, so staleness is jittering, not fixed.

UPDATE RATE. `ChunkMsg` at **2–5 Hz, event-triggered**, on any of: queue drained below 60% of the chunk (SmolVLA's `chunk_size_threshold`≈0.6); gripper state change; Cartesian tracking error >1.5 cm; wrench threshold crossed; the residual's forward-model prediction error saturating (i.e. "the world is not what A predicted"); operator interrupt. Below the interface: retimer emits Cartesian setpoints at **200 Hz**; impedance loop closes at **500–1000 Hz** on the arm's controller; residual runs in that loop at **1 kHz** (measured 0.05 ms).

WHAT THE INTERFACE BUYS YOU, which is the honest justification: it is human-readable and unit-testable. You can render it in RViz, drag it with a 6-DoF mouse, drive the arm through it before any model exists, replay a logged trace through the residual in CI, and — the thing that actually paid off in RT-H (+15% from hierarchy, but 40%→63% from *corrections*) — let a human intervene at the pose level and fold those corrections back into training.
TRAINING: STAGE 0 — the spine (days 1–4, ZERO learning, zero data). URDF → TRAC-IK → Ruckig retimer → Cartesian impedance on the arm controller → the fixed safety/reflex layer → the `ChunkMsg` schema and its replay tooling. Acceptance test: teleop the arm *through the interface* with a 6-DoF mouse writing `ChunkMsg` at 3 Hz. If you cannot do that, no amount of model training will help. This is also the moment you discover whether the arm exposes torque/impedance at all — if it accepts only joint positions, the stiffness channel is inert, the residual has almost nothing to correct, and you should scope v1 to free-space pick-and-place and skip Stage 2 entirely.

STAGE 1 — Model A (weeks 2–3).
• Teleop data: **50–80 episodes per task × 8–12 tasks = 400–1000 episodes**, LeRobot format, 30 fps, 2 cameras, ~6–10 hours of teleop across 5–8 days. This is the low end of the π0/SmolVLA regime (50–200 demos/task) because you are fine-tuning, not training from scratch.
• **Never train A from scratch.** LoRA (r=32) on the LM + full training of the action expert, starting from `lerobot/smolvla_base`. Random-init vs pretrained is ~20 points on LIBERO — larger than every short-horizon hierarchy premium in the entire literature (which is 0–9 points), and it is free.
• **The non-teleop data is the actual reason to have a high level, and skipping it forfeits the whole design.** Add: (a) ~750 hand-annotated still images with gripper-pose overlays — ~1 h to collect, ~2 h to annotate; RT-Affordance's affordance predictor collapsed 77% → 24% without exactly this. (b) Keep 20–30% web VQA/pointing data (RoboPoint-style pixel prediction) in the mixture; without web co-training theirs fell to 11%. (c) Hindsight-relabel every episode with subtask strings.
• Labels that cost nothing because they are already in the demos: log-stiffness from measured wrench ÷ tracking error during teleop; swivel angle from the recorded joint configuration; gripper aperture from the encoder; phase from gripper-state flips (this is how RT-Affordance auto-extracts keyframes).
• Losses: flow matching on the delta chunk (1.0×), L1 on log-stiffness and swivel (0.1×), CE on subtask string (0.2× — π0.5's "implicit HL" result says this auxiliary data is where most of the decomposition benefit actually lives), CE on gripper, L1 on the explicit position/rotation aux head (OpenHelix's biggest single gain).
• Compute: ~1 GPU-day on a rented A100 or 4090, ~$20–40. **Do not fine-tune on the Mac** — LoRA-only at 224² with grad accumulation would take 3–5 days.

STAGE 2 — the residual (week 4, and ONLY after Stage 1 is deployed). The ordering is the entire point.
• Roll out A + spine with **residual = 0** on the training scenes. Log at 200 Hz: commanded setpoint, measured pose, measured wrench, joint state, tracking error. ~2–4 hours of on-robot rollout, ~200–400 episodes, one day.
• Label = the error the classical impedance controller failed to close. The feedback controller's own output IS the motor-error teaching signal (Kawato's climbing-fiber analogue, Gomi & Kawato 1988). **No human labeling.**
• Losses: L2 on ΔF; an L1 magnitude penalty so it stays near zero (graceful degradation is a training objective, not a hope); L2 on the forward-model aux head predicting next-5ms wrench and joint state from the efference copy.
• Trains in ~20 minutes on the Mac's CPU. 0.183M params.
• **One DAgger round**: retrain on data collected with the residual active, because it changes the distribution it sees.

SEPARATE, NOT JOINT — and this is a feature, not a compromise. A and the residual are separated by a deterministic, *correct* classical block. There is no projector to pre-align, no latent to distill, no gradient to pass. This variant structurally cannot hit OpenHelix's failure mode where two separately-pretrained models scored 0/0/0/0/0 across every configuration without projector pre-alignment. It also cannot hit the GHOST/GHIL-Glue handoff shift in its severe form: IK is correct for *every reachable target in the workspace by construction*, including poses no demonstration ever visited, so A's prediction error propagates as a clean, diagnosable geometric miss rather than an off-manifold garbage command. The only thing exposed to A's error distribution is the 0.18M residual, whose output is hard-clipped to ±8 N — and Stage 2 trains it on exactly that distribution.

VERSIONING: `(A_version, residual_version, calibration_version)` is one deployable artifact and cannot be mixed. An offline CI test replays a fixed logged `ChunkMsg` trace through the residual and asserts command bounds and smoothness, so an A retrain fails CI instead of the robot.

ABLATION LADDER — run before believing anything, ≥50 rollouts per task per condition, blind randomized A/B:
 (0) A + spine, residual OFF — the baseline that must be beaten by everything else.
 (1) A + spine + residual.
 (2) Monolithic SmolVLA emitting joint positions, same data, matched effective rate via async chunking — the control the literature says will be a *tie* on short-horizon static tasks (69.57% vs 69.63%; HiRT real quasi-static 70.0 hierarchical vs 71.3 monolithic).
 (3) A with the auxiliary subtask/stiffness/pose heads removed — isolates whether the win was the data or the structure.
 (4) Oracle-A: replay demo ground-truth poses through the spine (upper bound on the low level). Oracle-B: A's live poses through pure IK+impedance (upper bound on A). Without these two you cannot attribute a single failure.
