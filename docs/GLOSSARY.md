# 용어집

이 프로젝트 문서에 나오는 용어를 **왜 중요한지**와 함께 정리했습니다.
분류가 아니라 **읽다가 막히는 순서**로 배치했습니다.

---

## 1. 이 프로젝트의 핵심 개념

### 대뇌 / 소뇌 (Model 1 / Model 2)
제안된 2모델 구조. **Model 1(대뇌)** 이 "손을 어디에 둘지"(목표 포즈)를 정하고, **Model 2(소뇌)** 가 "어떻게 움직일지"(관절값)를 정합니다.

> ⚠️ 이 비유는 신경과학적으로 부정확합니다. 실제 소뇌는 운동뉴런으로 직접 출력하지 않고, 다른 곳에서 만든 명령을 **보정**만 합니다. 소뇌를 제거하면 움직임이 엉성해지지 죽지 않는데(ataxia), Model 2를 제거하면 로봇이 정지합니다. 그래서 Model 2는 소뇌가 아니라 **척수 + 피질척수로**에 가깝습니다. → [메인 문서 4절](2026-07-28-dual-brain-architecture-analysis.md)

### monolith (단일 모델)
분리하지 않고 하나의 모델이 이미지에서 관절 명령까지 직접 내는 구조. **이 프로젝트의 비교 대상(baseline)** 입니다. "분리가 monolith를 이기는가"가 검증하려는 핵심 질문입니다.

### 인터페이스 (interface)
Model 1과 Model 2 **사이에 흐르는 데이터**. 이 프로젝트에서 가장 많이 논의된 대상입니다. 현재 제안은 "6-DoF 포즈"인데, 분석 결과 **여기에 그리퍼·시간·강성·상대 포즈가 빠져 있는 것**이 최대 결함으로 나왔습니다.

### 게이트 (gate) / 킬 게이트
**계획을 중단시킬 수 있는 판정 지점.** 값싼 실험으로 비싼 실험을 죽이는 것이 목적입니다. 이 프로젝트엔 두 개가 있습니다 — SDK 루프 레이트(GATE-1)와 E0(GATE-2).

## 2. 로봇 기구학

### DoF (Degree of Freedom, 자유도)
독립적으로 움직일 수 있는 축의 수. G1의 팔은 **7-DoF × 2**입니다.

### 포즈 (pose) / SE(3)
물체의 **위치(3) + 방향(3) = 6개 숫자**로 표현되는 자세. `SE(3)`는 이 6-DoF 공간의 수학적 이름입니다.

### EE (End-Effector, 엔드이펙터)
팔 끝의 도구. G1은 그리퍼입니다. **TCP**(Tool Center Point)는 그 도구의 기준점.

### FK (Forward Kinematics, 순기구학)
**관절값 → EE 포즈.** 항상 답이 하나이고 계산이 쉽습니다.

### IK (Inverse Kinematics, 역기구학)
**EE 포즈 → 관절값.** FK의 반대인데 훨씬 어렵습니다:
- 해가 **여러 개**일 수 있음 (팔꿈치를 위로 vs 아래로)
- 해가 **없을** 수도 있음 (팔이 닿지 않는 곳)

> 이것이 이 프로젝트 논쟁의 중심입니다. Model 2가 하려는 일이 사실상 IK인데, IK는 이미 정확하고 빠르게 풀립니다.

### underdetermined (미결정)
**답을 하나로 정하기에 조건이 부족한 상태.** 7-DoF 팔에 6-DoF 포즈만 주면 조건이 1개 모자라, 답이 무한히 많은 곡선(→ self-motion manifold)을 이룹니다.

### self-motion manifold
**EE는 그대로인데 팔 형상만 바뀌는 움직임의 집합.** 손을 책상 위 한 점에 고정한 채 팔꿈치를 위아래로 돌려보십시오 — 손은 안 움직이는데 팔꿈치는 움직입니다. 그 팔꿈치 궤적이 self-motion manifold입니다.

> **실측:** G1에서 EE를 0.16µm 이내로 고정한 채 팔꿈치가 **263mm** 움직입니다. ([검증 T3](../robot/test_kinematics.py))

### ψ (psi) / arm angle / swivel angle
**self-motion manifold 위의 위치를 나타내는 숫자 1개.** 어깨→손목 축을 중심으로 팔꿈치가 몇 도 돌아가 있는지.

> **이 프로젝트의 핵심 처방 중 하나:** 인터페이스에 ψ 하나(팔당 1개, 총 2개)를 추가하면 7-DoF가 **완전히 결정**됩니다. 신경망이 아니라 숫자 2개짜리 수정입니다. 그리고 **라벨은 공짜** — 기록된 관절값에 FK를 돌리면 나옵니다.

### S–R–S (Spherical–Revolute–Spherical)
7-DoF 팔의 특별한 구조: **어깨 3축이 한 점에 모이고 → 팔꿈치 1축 → 손목 3축이 한 점에 모임.**

> **G1이 여기 해당합니다** (URDF 검증: 축 집중 잔차 0.000000mm). 덕분에 `(포즈, ψ)`가 주어지면 **폐형 해석해(closed-form)** 가 존재합니다 — 반복 계산 없이 공식으로 풀린다는 뜻.

### closed-form (폐형해)
**공식으로 한 번에 풀리는 해.** 반복법(iterative)과 대비됩니다. 빠르고 정확하며 항상 같은 답을 줍니다.

### DLS (Damped Least Squares)
IK를 푸는 수치 방법 중 하나. 특이점 근처에서 폭주하지 않게 "감쇠"를 넣은 최소자승법.

### 특이점 (singularity)
팔이 특정 자세에서 **어떤 방향으로 움직일 능력을 잃는 지점.** 팔을 완전히 편 상태에서 더 뻗을 수 없는 것 같은 상황. 여기서 IK 해가 불안정해집니다.

### null space (영공간) / null-space posture
**EE에 영향을 주지 않으면서 팔이 움직일 수 있는 여유 공간.** self-motion manifold와 같은 것을 다른 각도에서 부르는 말. "null-space 자세"는 그 여유를 어떻게 쓸지의 선택입니다.

### redundancy (중복성)
필요한 것보다 자유도가 많은 상태. 7-DoF 팔로 6-DoF 작업을 하면 1개가 남습니다. **여유가 좋은 것**이지만(장애물 회피 등), 대신 "어떻게 쓸지" 정해줘야 합니다.

### 좌표계 (frame)
위치를 재는 기준. 이 프로젝트에 나오는 것들:

| 프레임 | 의미 |
|---|---|
| `base_link` | 로봇 전체의 기준 |
| `torso_base_link` | **목과 양팔이 갈라지는 강체.** 이 프로젝트의 기준 프레임 |
| `head_link2` / 헤드 프레임 | 목 pan/tilt 뒤의 카메라 기준 |
| arm base | 어깨 마운트 |

> **핵심 발견:** `head → arm_base` 변환은 **목 관절 2개에만** 의존합니다. 다리·허리 5관절과 이동 베이스는 목과 팔의 **공통 조상**이라 상대 변환에서 소거됩니다.

### extrinsic / intrinsic (외부/내부 파라미터)
- **intrinsic**: 카메라 자체의 성질 (초점거리, 렌즈 왜곡)
- **extrinsic**: 카메라가 **어디에 어떤 방향으로** 붙어 있는가

> G1은 **헤드 카메라 extrinsic이 공개돼 있지 않습니다.** 헤드 프레임 설계의 가장 핵심적인 수치인데 직접 측정하거나 벤더에 요청해야 합니다.

### hand-eye calibration (손-눈 캘리브레이션)
카메라와 팔의 상대 위치를 정밀 측정하는 작업. 전형적 잔여 오차 **~2.1mm / ~3.2°**. 이 오차가 **절대 포즈**에는 영구히 각인되고, **상대 델타**에서는 대부분 상쇄됩니다.

## 3. 제어

### servo loop / 서보 루프
관절이 목표 위치를 따라가게 하는 **저수준 고속 제어 루프** (보통 500~1000Hz+).

### PID / PD 제어
오차에 비례(P)·미분(D)·적분(I)해서 명령을 만드는 고전 제어. `Kp`는 비례 게인 — 클수록 뻣뻣하게 목표를 따라갑니다.

### impedance / admittance control
**로봇이 외력에 얼마나 "물렁하게" 반응할지**를 제어하는 방식.
- **impedance**: 위치 오차 → 힘 출력 (토크 명령 필요)
- **admittance**: 힘 측정 → 위치 목표 조정 (**위치 명령만으로 가능**)

> **G1은 팔에 위치 명령만 받습니다.** 따라서 impedance는 불가능하고 **admittance만 가능**하며, 그 품질은 루프 레이트에 좌우됩니다. GATE-1이 이것을 측정합니다.

### compliance (컴플라이언스)
로봇이 외력에 순응하는 성질. "물렁함". 접촉 작업(삽입, 닦기)에 필수적입니다.

> G1은 팔이 위치 전용이라 **학습된 컴플라이언스는 도달 불가**입니다. 단 **그리퍼만은 velocity/effort가 유효**해서 힘 제한 파지는 가능합니다.

### wrench (렌치)
**힘 3개 + 토크 3개 = 6개 숫자.** 접촉 상태를 나타냅니다. "스패너"가 아닙니다.

### F/T sensor (Force/Torque 센서)
wrench를 측정하는 센서. G1은 **손목에 6축 F/T가 표준 탑재**돼 있습니다.

> **이것이 이 프로젝트의 승부처입니다.** 벤더 자신의 모델(GraspVLA)은 힘을 전혀 안 쓰고, 공식 데이터 파이프라인은 힘을 **버립니다**. 접촉 인지 양팔 조작이 발표된 모든 것에서 진짜 구멍입니다.

### 폐루프 / 개루프 (closed-loop / open-loop)
- **폐루프**: 결과를 측정해서 되먹임 → 보정
- **개루프**: 명령만 내고 결과를 안 봄

### latency / jitter (지연 / 지터)
- **latency**: 입력에서 출력까지 걸리는 시간
- **jitter**: 그 시간의 **들쭉날쭉함**

> **jitter가 latency보다 위험합니다.** 평균 40ms인데 가끔 400ms로 튀는 시스템은 사람을 다치게 합니다. 그래서 평균이 아니라 **p99/p99.9**로 봅니다.

### p50 / p99 / p99.9 (백분위)
100번 중 50번째/99번째로 느린 값. **p99.9는 1000번 중 999번째.** 최악에 가까운 경우가 얼마나 나쁜지 봅니다.

### Bode 선도
주파수별로 시스템이 얼마나 잘 따라가는지(gain)와 얼마나 늦는지(phase)를 그린 그래프. **-3dB 지점**이 "성능이 절반으로 떨어지는 주파수" = 대역폭입니다.

### staleness (낡음)
받은 데이터가 **얼마나 오래된 것인가.** Model 1이 500ms 전에 만든 목표를 Model 2가 지금 쓰면 staleness가 500ms입니다. 그 사이 로봇이 움직였으면 목표가 틀어집니다.

### watchdog / deadman
**신호가 끊기면 자동으로 안전 정지**시키는 장치. 필수 안전 요소입니다.

## 4. 학습 / VLA

### VLA (Vision-Language-Action model)
**이미지 + 언어 지시 → 로봇 행동**을 내는 모델. 이 분야의 현재 주류입니다. π0, OpenVLA, GR00T, SmolVLA 등.

### policy (정책)
강화학습/모방학습에서 **"상태를 보고 행동을 결정하는 함수"**. 여기선 그냥 로봇 제어 모델을 뜻합니다.

### 모방학습 (imitation learning) / BC (Behavior Cloning)
**사람 시연을 따라 하도록 학습**시키는 방식. 텔레오퍼레이션 데이터로 학습하는 것이 여기 해당합니다.

### 텔레오퍼레이션 (teleoperation, 텔레옵)
사람이 원격으로 로봇을 조종하는 것. **학습 데이터를 만드는 방법**입니다.

### leader-follower / bilateral
텔레옵 장치 구조:
- **leader**: 사람이 잡고 움직이는 쪽
- **follower**: 따라 움직이는 실제 로봇
- **bilateral(양방향)**: 로봇이 받는 **힘을 사람도 느끼는** 구조

> **중요:** 리그가 bilateral이 아니면 조작자가 접촉을 못 느낀 것이고, 그러면 **wrench 채널에 학습 가능한 구조가 없습니다.** 힘 관련 계획 전체의 전제조건입니다.

### action chunk / chunking
한 번에 **여러 스텝의 행동을 묶어서** 예측하는 것. 모델이 느려도 부드럽게 움직일 수 있습니다.

> **실측:** ACT에서 1스텝씩 내면 성공률 **1%**, 100스텝 묶으면 **44%**. 거의 공짜인데 효과가 큽니다.

### absolute / delta (절대 / 상대)
- **절대**: "여기로 가라" (고정 기준)
- **델타**: "여기서 이만큼 더 가라" (현재 기준)

> **실측:** EE 절대 69.0% vs **EE 델타 89.6%**. 델타가 캘리브레이션 오차를 상쇄하기 때문입니다.

### ablation (제거 실험)
**어떤 요소를 빼보고 성능이 얼마나 떨어지는지** 재는 실험. 무엇이 실제로 기여하는지 알아내는 방법.

> 이 프로젝트의 3방향 ablation: RGB / F/T / 포즈를 각각 0으로 만들어보고 패턴으로 Model 2가 실제로 뭘 하고 있는지 진단합니다.

### baseline (기준선)
**이겨야 할 대조군.** 여기선 "단일 모델" 또는 "해석적 IK + admittance"입니다.

### oracle (오라클)
**현실에서는 얻을 수 없는 완벽한 정보.** "정답 포즈를 그냥 알려줬을 때" 성능을 재면 **아키텍처의 천장**을 알 수 있습니다.

> E0의 핵심 아이디어입니다. 오라클로도 monolith를 못 이기면, 실제 Model 1은 더 못할 게 확실하므로 만들 이유가 없습니다.

### hindsight (사후 라벨링)
**나중에 일어난 일을 보고 되돌아가서 라벨을 붙이는 것.** 시연에서 "t+k 시점에 손이 어디 있었는지"를 목표 포즈 라벨로 쓰는 것이 hindsight labeling입니다.

### covariate shift / cascaded distribution shift (분포 이동)
**학습할 때 본 입력과 실제 쓸 때 받는 입력이 다른 문제.**

> Model 2를 "정답 포즈"로 학습시키고 실제로는 "Model 1의 부정확한 포즈"를 주면 이게 일어납니다. 측정된 대가가 큽니다 — 핸드오프만 고쳐서 실기체 54% → 70%.

### DAgger
covariate shift를 고치는 방법. **모델을 실제로 굴려보고, 그때 나온 (틀린) 입력에 정답을 다시 붙여 재학습**합니다.

### residual (잔차)
**기존 방식 위에 얹는 보정값.** `최종 = 고전_IK(목표) + 학습된_보정`.

> **이 프로젝트의 핵심 처방.** 보정이 0이면 고전 스택이 그대로 살아나므로 **안전하게 실패**합니다. 그리고 IK가 설명하는 부분(손실의 ~99%)을 미리 빼주므로 학습 모델이 **힘 정보에 집중**하게 됩니다.

### gating (게이팅)
**조건에 따라 신호를 켜고 끄는 것.** 접촉 중일 때만 힘 정보를 쓰게 하는 것이 contact gating입니다.

> **실측:** 힘을 그냥 이어붙이면 +2.9%p, 게이팅 등 구조를 넣으면 **+23.2%p**. 같은 정보인데 8배 차이.

### fine-tuning / LoRA
- **fine-tuning**: 이미 학습된 모델을 내 데이터로 추가 학습
- **LoRA**: 전체가 아니라 **작은 부분만** 학습해서 메모리를 아끼는 기법

### pretraining (사전학습)
대규모 데이터로 미리 학습된 상태. **랜덤 초기화 대비 ~20%p 차이** — 이 프로젝트의 어떤 아키텍처 선택보다 큽니다.

### embodiment (임베디먼트)
**로봇 몸체의 종류.** 팔 개수, 관절 수, 그리퍼 종류 등. "cross-embodiment"는 다른 로봇에도 통하는 모델을 뜻합니다.

### rollout (롤아웃)
정책을 실제로 처음부터 끝까지 한 번 굴려보는 것. **평가 단위**입니다.

### sim-to-real (sim2real)
시뮬레이션에서 학습한 것을 실기체로 옮기는 것. **접촉이 있으면 잘 안 됩니다** — 시뮬레이터가 접촉 물리를 제일 못 맞추기 때문입니다.

## 5. 시스템 / 하드웨어

### SDK (Software Development Kit)
로봇을 제어하는 공식 라이브러리. **GalbotSDK는 Linux 전용**이라 Mac에서는 로봇과 통신할 수 없습니다.

### URDF / MJCF
로봇의 **형상과 관절을 기술한 파일**.
- **URDF**: ROS 표준
- **MJCF**: MuJoCo 시뮬레이터용

### MuJoCo / Isaac Sim / RoboTwin
물리 시뮬레이터.
- **MuJoCo**: 가볍고 빠름, **Mac에서 동작** (G1 모델 89.5× 실시간 확인)
- **Isaac Sim/Lab**: NVIDIA, 포토리얼 렌더링, **CUDA 전용 + 16GB VRAM 필요**
- **RoboTwin 2.0**: 양팔 특화 벤치마크(50작업), CUDA 필요

### LeRobot
HuggingFace의 로봇 학습 프레임워크 + **데이터셋 포맷**. Galbot도 이 포맷으로 변환하는 공식 도구를 제공합니다.

### MCAP
로봇 데이터 기록 포맷. G1의 텔레옵 기록이 이걸로 저장되고, LeRobot 포맷으로 변환해서 학습에 씁니다.

### RoboCOIN
BAAI가 공개한 **실기체 G1 양팔 데이터셋** (~2,974 에피소드 / 2.02M 프레임 / 18.7시간).

> ⚠️ **F/T 채널이 없습니다.** 힘 관련 질문은 여기서 답할 수 없습니다.

### TensorRT
NVIDIA의 추론 최적화 도구. **엔진이 GPU 아키텍처에 종속**돼서, Orin용 엔진은 Orin에서 빌드해야 합니다.

### AGX Orin
NVIDIA의 로봇/엣지용 컴퓨터. G1에 탑재돼 있고, 개인 소유분이 **배포 타깃 트윈** 역할을 합니다.

### VRAM
GPU 메모리. **모델 크기의 상한**을 정합니다. 이 프로젝트 기준: Isaac Lab 16GB, π0 파인튜닝 24GB.

### MPS / MLX / CUDA
GPU 연산 백엔드.
- **CUDA**: NVIDIA
- **MPS / MLX**: Apple Silicon

> **실측 함정:** Mac에서 batch-1 추론은 **FLOP이 아니라 dispatch 바운드**라, 작은 모델은 **CPU가 MPS보다 빠릅니다** (ViT-B: CPU 44.7ms vs MPS 64.2ms).

## 6. 근거 표기

문서에서 수치 옆에 붙는 태그입니다. **어떤 수치를 믿을 수 있는지** 구분하려고 씁니다.

| 태그 | 의미 | 신뢰도 |
|---|---|---|
| **[M]** | 이 기기/이 로봇에서 **직접 측정** | 최상 — 인용 가능 |
| **[P]** / **[PR]** | 동료심사 논문 | 높음 |
| **[X]** / **[PP]** | 2025–26 preprint, 검증 안 함 | **방향성만** — 인용 전 원문 확인 |
| **[V]** | 벤더 블로그, ablation 없음 | 구조 설명만 신뢰 |
| **[I]** | 추론 | 측정도 인용도 아님 |

> **`[X]` 수치를 투자자 자료나 대외 문서에 인용하기 전에 반드시 원문을 확인하십시오.** 실제로 이 프로젝트에서 두 건의 인용 오류가 발견됐습니다 (8%/94% 오분류, OC-VLA "14% vs 29%"는 논문에 없는 수치).

## 8. 헷갈리기 쉬운 것

| 비슷해 보이지만 다른 것 | 차이 |
|---|---|
| **latency vs jitter** | 얼마나 늦나 vs 얼마나 들쭉날쭉하나. **jitter가 더 위험** |
| **impedance vs admittance** | 힘을 명령 vs 위치를 명령. **G1은 admittance만 가능** |
| **절대 vs 델타 포즈** | 고정 기준 vs 현재 기준. **델타가 20%p 낫다** |
| **FK vs IK** | 관절→포즈(쉬움) vs 포즈→관절(어려움, 다중해) |
| **oracle vs 배포** | 정답을 줬을 때 vs 실제. **격차가 곧 상류 모델의 오차** |
| **성공률 vs MTBI** | 한 번 성공 확률 vs **개입 없이 몇 번 연속**. 상업 기준은 후자 |
| **6-DoF vs 7-DoF** | 6은 결정됨, **7은 ψ가 없으면 미결정** |
