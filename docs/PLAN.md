## 1. 두 개의 킬 게이트

서로 독립이라 **병렬로 돌립니다.** 둘 중 하나라도 걸리면 아래 계획 대부분이 무의미해지므로, 모델 코드를 쓰기 전에 통과시킵니다.

### 🔴 GATE-0 — SDK 시그니처 확정 (회사, **로봇 불필요**)

**2026-07-31 신설.** `galbot_sdk` 는 pybind11 확장이라 `inspect.signature()` 가 전부 `(?)` 로 나옵니다. **메서드 이름은 확정, 인자는 미확인**입니다. 실인자는 docstring 안에 있고 `make probe` 가 긁습니다. 몇 분이면 끝나고 로봇도 필요 없는데, 이게 GATE-1 어댑터를 확정합니다.

실행: `make probe` → `make probe-live` (자세한 것은 [RUNBOOK §2-1](RUNBOOK.md))

### 🔴 GATE-1 — SDK 폐루프 대역폭 (회사)

**2026-07-31 개정 — 명령 경로가 둘임이 드러나 판정을 분리했습니다.**

| | 경로 | 재는 것 |
|---|---|---|
| **PART A** | 관절 위치 명령 고속 반복 | 명령 rate 천장 + jitter |
| **PART B** | 동일 | 위치 추종 −3dB 대역폭 |
| **PART C** | `execute_joint_trajectory` + `TARGET_TYPE_OVERRIDE` | **재계획 지연(replan latency)** |

**왜 개정했는가.** 이전 판정은 상위에서 명령을 고속 반복하는 **단일 경로**만 가정하고 "천장 <50Hz → 분리 전제 붕괴"라고 썼습니다. 그런데 SDK 표면에 궤적 큐 덮어쓰기 의미론(`TARGET_TYPE_OVERRIDE / PROVERRIDE / PREPENDNOW`)이 따로 있었습니다. 그 경로가 동작하면 **상위가 5Hz여도 온보드가 보간**하므로 그 논리는 성립하지 않습니다.

**경로 B가 살아 있으면 그쪽이 주 판정 기준**이고, 경로 A 천장은 보조 지표입니다.

| 재계획 지연 p95 (경로 B) | 결론 |
|---|---|
| **≤50 ms** | ✅ 5Hz chunk 스트리밍 성립. 상위 rate가 낮아도 무방 |
| 50–200 ms | 경계. 청크 주기를 그보다 길게, 접촉 반응이 그만큼 늦음 |
| **>200 ms** | 🔴 청크 경계마다 이미 지난 상황에 반응 |

경로 B를 못 쓸 때만 기존 기준을 적용합니다.

| 명령 rate 천장 (경로 A) | 결론 |
|---|---|
| **≥100 Hz** | admittance 작동 → 분리 유지 가능 |
| 50–100 Hz | 경계 |
| **<50 Hz** | 🔴 **분리 전제 붕괴.** 단일 모델 + 벤더 WBC로 |

> ⚠️ **천장은 "확인됨"과 "미확인"이 다릅니다.** `achieved_hz` 는 우리가 함수를 호출한 횟수입니다. 송신이 fire-and-forget 비동기 publish 면 로봇이 실행했는지와 무관하게 올라갑니다. 이걸 반증할 유일한 증거는 **로봇이 준 타임스탬프로 본 상태 갱신률**이고, 로봇 타임스탬프가 없으면 그 증거가 원리적으로 없어 스크립트가 PASS 를 거부합니다.
>
> ⚠️ **3090에 다른 부하가 없을 때 측정하십시오.** jitter를 재는데 다른 워크로드가 돌면 p99/p99.9가 오염됩니다.

> **아직 미측정으로 남는 것:** `set_joint_commands` / `set_joint_commands_batch` 는 현재 코드가 한 번도 호출하지 않습니다(위치 명령 사다리를 탑니다). 청크 경계의 이음매 연속성도 측정 축이 없습니다.

실행: `make gate1-real HOST=external`

### 🔴 GATE-2 — E0, 가능한 가장 값싼 반증 (집, 1660)

oracle 인터페이스(hindsight 정답 미래 EE 포즈)로 저수준 정책을 학습 → **아키텍처의 천장** 측정. 앞으로 만들 어떤 Model 1도 정답을 이길 수 없습니다.

LIBERO-Spatial + Object (20작업, 데모 1000개 동봉), ~25M 모델 3개, 3 seed × 500 ep.

| Arm | 정의 |
|---|---|
| **C0 MONO** | RGB + proprio → action chunk |
| **C6 SPLIT-ORACLE** | 정답 목표 포즈 + 관절 + RGB → action chunk |
| **C8 ORACLE-IK** | 정답 목표 포즈 → `OSC_POSE`, **학습 파라미터 0** |

| 결과 | 결론 |
|---|---|
| `C6 − C0 ≤ +5` 또는 CI∋0 | **가설 사망.** 천장이 얇으면 배포된 분리는 monolith 아래로 확실히 감 |
| `C8 ≥ C6 − 5` | **학습 Model 2 사망.** Model 1 + closed-form S–R–S IK로 |
| `C6 − C0 ≥ +10` 그리고 `C6 − C8 ≥ +5` | 진행 |

> ACT 하네스 재현은 **생략** — 이미 ACT 실행 경험 있음.

## 6. 벤더 문의 목록

공개 소스로 불가, 영업/FAE 담당 사안:

**2026-07-31 갱신 — SDK 실물 표면 확인으로 일부가 자체 해결되거나 질문이 날카로워졌습니다.** ([RUNBOOK §7](RUNBOOK.md) 과 동기화)

1. 🔴 **`TARGET_DATA_JOINT_EFFORT` / `TARGET_DATA_FRAME_WRENCH` 가 G1 팔에서 실제로 지원되는가**
   SDK enum 에 **존재는 확인**됐으나 `UNSUPPORTED_FUNCRION` 에러 코드가 있어 **선언 ≠ 지원**입니다. 지원되면 **컴플라이언스 지향 Model 2가 되살아납니다.** 기존 `*_PVT_BYPASS_CTRL` 질문을 대체하는 **가장 가치 높은 질문** (PVT_BYPASS 는 하위 질문으로 강등)
2. 🔴 **`TARGET_TYPE_OVERRIDE` / `PROVERRIDE` / `PREPENDNOW` 의 정확한 의미론** — 큐를 어디서부터 자르는가, 실행 중인 점을 어떻게 이어붙이는가. **action chunk 스트리밍 설계가 직접 걸립니다.** GATE-1 PART C 가 지연은 실측하지만 의미론은 문서가 필요
3. **F/T 데이터시트** — 값 자체는 `make probe-live` 로 얻지만 **중력·페이로드 보상 여부는 값만 봐선 판별 불가.** 그 부분만 남음
4. ~~**헤드 카메라 외부 파라미터**~~ → ✅ **`get_sensor_extrinsic()` 로 자체 확인.** 문의 불필요
5. **세대 확인** → 🟡 클래스명이 `GalbotOne**Foxtrot**Sensor` 이므로 **Foxtrot 유력**. 관절 수는 `get_joint_names()` 로 확정. **정식 모델명만** 남음
6. **안전 인증** — ISO 10218 / 13849 PL / TS 15066 / TÜV / CE 근거를 어떤 출처에서도 못 찾음
7. SDK가 평면 LAN에 **하드코딩 root 자격증명**을 실어 보냄 — 엔터프라이즈 수용 불가
