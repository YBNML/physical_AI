## 1. 두 개의 킬 게이트

서로 독립이라 **병렬로 돌립니다.** 둘 중 하나라도 걸리면 아래 계획 대부분이 무의미해지므로, 모델 코드를 쓰기 전에 통과시킵니다.

### 🔴 GATE-1 — SDK 폐루프 대역폭 (회사)

`set_joint_commands`의 실제 명령 rate와 latency/jitter. **모든 공개 출처에서 미문서화**이고, SDK 자체 `example8_real_time_control_loop.cpp`는 이름과 달리 `sleep_for(1s)`가 든 1Hz 데모입니다.

| 결과 | 결론 |
|---|---|
| **~30 Hz** | 빠른 Model 2가 Model 1보다 의미 있게 빠를 여지 없음 → **대뇌/소뇌 분리 전제 붕괴.** 단일 모델 + 벤더 WBC로 |
| **~125 Hz** | admittance가 실제로 작동 → 분리 유지 가능 |

> ⚠️ **3090에 다른 부하가 없을 때 측정하십시오.** jitter를 재는데 다른 워크로드가 돌면 p99/p99.9가 오염됩니다.

실행: `tools/measure_loop_rate.py`

### 🔴 GATE-2 — E0, 가능한 가장 값싼 반증 (집, 1660)

oracle 인터페이스(hindsight 정답 미래 EE 포즈)로 저수준 정책을 학습 → **아키텍처의 천장** 측정. 앞으로 만들 어떤 Model 1도 정답을 이길 수 없습니다.

LIBERO-Spatial + Object (20작업, 데모 1000개 동봉), ~25M 모델 3개, 3 seed × 500 ep.

| Arm | 정의 |
|---|---|
| **C0 MONO** | RGB + proprio → action chunk |
| **C6 SPLIT-ORACLE** | 정답 목표 포즈 + 관절 + RGB → action chunk |
| **C8 ORACLE-IK** | 정답 목표 포즈 → `OSC_POSE`, **학습 파라미터 0** |

| 결과 | 결론 |
|---|---|
| `C6 − C0 ≤ +5` 또는 CI∋0 | **가설 사망.** 천장이 얇으면 배포된 분리는 monolith 아래로 확실히 감 |
| `C8 ≥ C6 − 5` | **학습 Model 2 사망.** Model 1 + closed-form S–R–S IK로 |
| `C6 − C0 ≥ +10` 그리고 `C6 − C8 ≥ +5` | 진행 |

> ACT 하네스 재현은 **생략** — 이미 ACT 실행 경험 있음.

## 2. 분기에 관계없이 확정인 것

판정을 기다리지 말고 지금 확정하십시오. **둘은 데이터 수집 후 소급 불가입니다.**

| # | 항목 | 이유 |
|---|---|---|
| **F1** | 🔴 **F/T를 데이터 파이프라인에** | 공식 `mcap2lerobot`의 출력 parquet에 **F/T 채널 0개.** 기록된 에피소드에 소급 추가 불가. **에피소드 1개 수집 전에** |
| **F2** | 🔴 **그리퍼 채널 추가** (14 → 16차원, 연속 폭) | Galbot 23차원 액션 벡터에 이미 있음. 14차원 정책은 9개 차원을 버림 → **파지 성공률 구조적으로 0%** |
| **F3** | **프레임 변환을 인터페이스에서** | 촬영시각 `head_joint1/2`로 `torso_base_link` 변환. 0.6m에서 목 1도당 ~10mm |

## 3. 작업 목록

### 🏢 회사에서만 가능 (우선순위 순)

- [ ] **C1** — `measure_loop_rate.py` 실행: 명령률 램프 + 스윕 사인 Bode. 온보드 HPU와 3090 양쪽에서 → **GATE-1**
- [ ] **C2** — 엔드이펙터 실물 확인: 양쪽 다 그리퍼인가, 한쪽이 석션컵인가 *(출처 3개가 답이 3개)*
- [ ] **C3** — 온보드 컴퓨트 확인: AGX Orin 64GB 맞는지, 개인 Orin과 같은 세대인지

### 🏠 집 — Mac

## 4. 판정표

| GATE-1 | GATE-2 | M2 | → 결론 |
|---|---|---|---|
| — | `C6−C0 ≤ +5` | — | **분리 포기.** 단일 VLA + 벤더 WBC. 2주면 로봇이 움직임 |
| — | `C8 ≥ C6−5` | — | **학습 Model 2 포기.** Model 1 + closed-form S–R–S IK |
| ~30 Hz | 통과 | — | 분리는 유지하되 **주파수 근거 삭제.** 데이터 재사용·검사 가능성으로 재정당화 |
| — | — | ≥15° | **헤드 프레임 폐기**, Model 1이 `torso_base_link`로 직접 예측 |
| 통과 | 통과 | ≤2° | 인터페이스 수정 후 진행 (그리퍼·dt·ψ·상대 포즈 추가) |

> **현재 근거 기준 가장 가능성 높은 결말은 `C8 ≥ C6−5`** — 벤더가 WBC를 출하하고, Galbot 자신의 연구자도 소뇌를 학습시키지 않고 손으로 쓴 Cartesian impedance 컨트롤러를 썼습니다.

## 5. 확정된 G1 사실 (URDF 직접 파싱으로 재확인)

`robot/assets/g1_joints_raw.json`

| 항목 | 값 |
|---|---|
| 팔 | **7-DoF × 2**, canonical S–R–S. 상완 **0.350m** + 전완 **0.360m** = 0.710m |
| 팔 관절 한계 | j1 ±3.0043, j2 ±1.6081, j3 ±2.9170, j4 −2.5680/+1.8699, j5 ±2.9170, j6 −0.8227/+0.7354, j7 ±1.5382 rad |
| 팔 effort | 60/60/30/30/10/10/10 N·m — 속도는 전 관절 1.5 rad/s *(플레이스홀더로 의심, 미확인)* |
| 목 | **2-DoF.** pan ±1.5208 (±87.1°), tilt −0.2143/+0.4936 (**총 40.6°만**) |
| 다리/허리 | **5, 전부 revolute** (프리즘 아님). `leg_joint4` = 허리 요 ±1.5906 (±91.1°) |
| torso 분기 | 목·양팔 전부 **fixed** — head [0, 0.3771, 0], 좌팔 [+0.2084, 0.172, 0], 우팔 [−0.2084, 0.172, 0] |
| 어깨 간격 | **0.4168 m** |
| 그리퍼 | 0 ~ 1.7030 rad, effort 50 N·m, vel 0.5 — **연속 폭** |
| 명령 인터페이스 | **위치 전용.** 그리퍼만 velocity/effort 유효 |
| 손목 F/T | 표준 탑재, 정식 API. **단 기본 데이터 경로에 없음** |

**head→arm_base는 목 관절 2개에만 의존합니다** — 다리/허리 5개와 평면 베이스 3개는 목과 양팔의 공통 조상이라 상대 변환에서 소거됩니다. 단 **환경 고정 목표**에서는 미관측이 2 → 10개로 뜁니다(베이스 오도메트리 채널 없음).

## 6. 벤더 문의 목록

공개 소스로 불가, 영업/FAE 담당 사안:

1. **`*_PVT_BYPASS_CTRL` semantics** — "bypass"가 effort나 Kp/Kd를 전달하는가 *(전달하면 컴플라이언스 지향 Model 2가 되살아남 — 가장 가치 높은 질문)*
2. **F/T 데이터시트** — 제조사/범위/분해능/노이즈/샘플레이트/마운팅 프레임, **중력·페이로드 보상 여부**
3. **헤드 카메라 외부 파라미터** (`head_link2` 기준) + 모델·FOV·스테레오 baseline
4. **세대 확인** (Charlie / Foxtrot / Golf / `G1_V2.2B`) — 세대 간 관절 수가 다름
5. **안전 인증** — ISO 10218 / 13849 PL / TS 15066 / TÜV / CE 근거를 어떤 출처에서도 못 찾음
6. SDK가 평면 LAN에 **하드코딩 root 자격증명**을 실어 보냄 — 엔터프라이즈 수용 불가
